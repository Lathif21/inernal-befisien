# 02 — Data Model

Postgres on **Neon**, accessed through **Drizzle ORM**. All tables use `uuid` primary keys (`gen_random_uuid()`), plus `created_at` / `updated_at` (`timestamptz`, default `now()`).

Money is stored as **`bigint` in whole Rupiah** (IDR has no cents in practice). Never use `float` or `numeric` with decimals for money.

## Entity overview

```
user ─┬─< deal.owner_id / project.owner_id / action.assignee_id / strategy_plan.owner_id
      └─< activity.user_id

client ─┬─< contact
        ├─< deal ──────┬─< action (deal_id)
        │              └─1 project (deal_id, nullable)
        ├─< project ───┬─< action (project_id)
        │              └─< transaction (project_id)
        ├─< strategy_plan ──< action (plan_id, optional)
        ├─< ai_suggestion
        ├─< transaction (client_id)
        └─< activity

category ─< transaction
invoice (P2) ─< invoice_item ;  invoice ─< transaction (payments)
```

### `action` (a step; replaces the old one-open-`next_action` table)

| Column             | Type                           | Notes                                                                                |
| ------------------ | ------------------------------ | ------------------------------------------------------------------------------------ |
| id                 | uuid PK                        |                                                                                      |
| deal_id            | uuid → deal, nullable          | Exactly one of `deal_id` / `project_id` is set (check constraint)                    |
| project_id         | uuid → project, nullable       |                                                                                      |
| plan_id            | uuid → strategy_plan, nullable | null = quick step with no plan                                                       |
| title              | text, not null                 | e.g. "Follow up proposal via WA"                                                     |
| due_at             | **timestamptz**, not null      | Date **and time** (entered in WIB)                                                   |
| all_day            | boolean                        | default `false`. When true, the UI hides the time and "late" starts after 23:59 WIB. |
| sort               | smallint                       | Order inside a plan                                                                  |
| assignee_id        | text → user                    |                                                                                      |
| done_at            | timestamptz                    | null = open                                                                          |
| done_by            | text → user                    |                                                                                      |
| from_suggestion_id | uuid → ai_suggestion, nullable |                                                                                      |

**Rule: next action of a card** = `min(due_at)` among the open actions of that deal or project.
**Rule: every active card has at least one open action.** Enforced in the service layer (completing the last open action prompts for a new one), not by a DB constraint, because plans legitimately hold several open steps.

**Late** = `done_at is null and due_at < now()`. **Due today** = `due_at` falls on today's date in WIB.

### Phase 2: `invoice`, `invoice_item`

`invoice`: `id, number (unique), client_id, project_id?, issue_date, due_date, status, subtotal, ppn_rate (default 11), ppn_amount, pph23_rate (default 2), pph23_amount, total, notes, sent_at`

`invoice_item`: `id, invoice_id, description, qty (numeric(10,2)), unit_price (bigint), amount (bigint), sort`

Totals are computed on the server and stored, never trusted from the client:

```
subtotal     = Σ item.amount
ppn_amount   = round(subtotal × ppn_rate / 100)        (if PPN on)
pph23_amount = round(subtotal × pph23_rate / 100)      (if PPh 23 on, withheld by the client)
total        = subtotal + ppn_amount                    (invoice face value)
expected_cash= total − pph23_amount                     (what actually reaches the bank)
```

## Business rules (enforced in server code)

1. **Stage change** → update `stage`, `stage_changed_at`, `position`. Insert an `activity` of type `stage_change`.
2. **Deal → `won`** → set `won_at`. If the user confirms, create a `project` (`onboarding`, `contract_value = value_estimate`, same client, `deal_id` set). Set `client.status = active`.
3. **Deal → `lost`** → require `lost_reason`, set `lost_at`, close its open actions, and set its active plan to `dropped`.
4. **Complete an action** → set `done_at` and `done_by`, log an `activity` (`action_done`). If the deal or project has no open action left, prompt for one (skippable only for terminal stages: `won`, `lost`, `done`). If all steps of a plan are done, offer to mark the plan `achieved`.
   4b. **Deal → `won` with a plan** → move the plan to the new project (`project_id` set, `deal_id` kept for history).
   4c. **Accept an AI suggestion** → create an action (or a plan), set `from_suggestion_id`, mark the suggestion `accepted`, and log an `activity` (`ai_accepted`).
5. **Transaction created, edited or deleted** → log an `activity` (`transaction`). Totals are always computed by queries, never stored on the client.
6. **Archive client** → only allowed when there are no open deals or projects (or confirm to archive them all).

## Ordering inside kanban columns

Use **fractional indexing** (`fractional-indexing` npm package) on `position`:

- When a card is dropped between A and B: `position = generateKeyBetween(A.position, B.position)`.
- Only the moved card is written. No reindexing of the whole column.
- Sort columns by `position asc`.

## Key queries

```sql
-- Client profit (paid only)
select
  coalesce(sum(amount) filter (where type='income'  and status='paid'),0) as income,
  coalesce(sum(amount) filter (where type='expense' and status='paid'),0) as expense,
  coalesce(sum(amount) filter (where type='income'  and status='planned'),0) as income_planned
from transaction where client_id = $1;

-- Dashboard "View by Waktu": totals per bucket ($1 = 'day' | 'week' | 'month' | 'year', $2/$3 = range)
select date_trunc($1, date) as bucket, type, sum(amount)
from transaction
where status='paid' and date between $2 and $3
group by 1,2 order by 1;

-- Dashboard "View by Klien": top 10 clients by income in the period, rest = Lainnya (done in code)
select client_id,
  sum(amount) filter (where type='income')  as income,
  sum(amount) filter (where type='expense') as expense
from transaction
where status='paid' and date between $1 and $2
group by client_id order by income desc nulls last;

-- Previous period for "vs periode sebelumnya": same query, range shifted back by one period length.

-- Strategi pagination: 3 plans per page, then 4 steps per plan page
select * from strategy_plan where status='active' order by target_date nulls last, created_at
limit 3 offset ($1 - 1) * 3;
-- page holding the first unfinished step: floor((count of steps before it) / 4) + 1
select * from action where plan_id = $1 order by sort, due_at limit 4 offset ($2 - 1) * 4;

-- Next action per card
select distinct on (deal_id) * from action
where done_at is null and deal_id = any($1)
order by deal_id, due_at;

-- Late / today / tomorrow for the digest (WIB)
select a.*, coalesce(d.client_id, p.client_id) as client_id
from action a
left join deal d on d.id = a.deal_id
left join project p on p.id = a.project_id
where a.done_at is null and a.assignee_id = $1
  and a.due_at < (date_trunc('day', now() at time zone 'Asia/Jakarta') + interval '2 day') at time zone 'Asia/Jakarta'
order by a.due_at;
```

## Indexes

- `deal (stage, position)`, `project (stage, position)`
- `action (assignee_id, due_at) where done_at is null`
- `action (deal_id, due_at) where done_at is null`, `action (project_id, due_at) where done_at is null`, `action (plan_id, sort)`
- `strategy_plan (status, target_date)`, `ai_suggestion (status, created_at desc)`
- `transaction (client_id, date)`, `transaction (date, type, status)`
- `activity (client_id, occurred_at desc)`
- `client (lower(name))` for search (later: `pg_trgm`)

## Drizzle sketch (excerpt)

```ts
// src/lib/server/db/schema/crm.ts
import {
	pgTable,
	pgEnum,
	uuid,
	text,
	bigint,
	date,
	timestamp,
	smallint,
	boolean,
	jsonb,
	index,
	uniqueIndex,
	check
} from 'drizzle-orm/pg-core';
import { sql } from 'drizzle-orm';
import { user } from './auth';

export const dealStage = pgEnum('deal_stage', [
	'lead',
	'contacted',
	'meeting',
	'proposal',
	'negotiation',
	'won',
	'lost'
]);

const ts = {
	createdAt: timestamp('created_at', { withTimezone: true }).defaultNow().notNull(),
	updatedAt: timestamp('updated_at', { withTimezone: true })
		.defaultNow()
		.notNull()
		.$onUpdate(() => new Date())
};

export const deal = pgTable(
	'deal',
	{
		id: uuid('id').primaryKey().defaultRandom(),
		clientId: uuid('client_id')
			.notNull()
			.references(() => client.id),
		title: text('title').notNull(),
		stage: dealStage('stage').notNull().default('lead'),
		position: text('position').notNull(),
		valueEstimate: bigint('value_estimate', { mode: 'number' }),
		ownerId: text('owner_id').references(() => user.id),
		lostReason: text('lost_reason'),
		stageChangedAt: timestamp('stage_changed_at', { withTimezone: true }).defaultNow().notNull(),
		wonAt: timestamp('won_at', { withTimezone: true }),
		lostAt: timestamp('lost_at', { withTimezone: true }),
		...ts
	},
	(t) => [
		index('deal_stage_pos').on(t.stage, t.position),
		check('lost_needs_reason', sql`${t.stage} <> 'lost' or ${t.lostReason} is not null`)
	]
);
```

> Note: Better Auth's `user.id` is `text` by default, so foreign keys to `user` are `text`. All other IDs are `uuid`.
> `bigint` in `mode: 'number'` is safe up to about 9 quadrillion Rupiah, far beyond any realistic total.
